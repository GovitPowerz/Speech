# Validation: oracles, goldens and the standing gates

How far the port can be trusted and on what evidence. Three questions, three sections: how parity against the 2015 system was established (the ladder), what produced the fixtures the tests compare against (the oracle tiers), and which invariants every later change is held to (the standing gates). The decisions behind the gates are [ADR-0001](adr/0001-port-truth-after-the-parity-tag.md) to [ADR-0004](adr/0004-streaming-changes-timing-never-arithmetic.md); the measured numbers are in [RESULTS.md](../RESULTS.md).

## The parity ladder

Parity is verified as a layered ladder, each rung golden-tested against the legacy oracle before the next is trusted:

1. **Golden features** - feature extraction bit-for-bit against legacy `.mat` dumps.
2. **Weight roundtrip** - flat weight-vector `.bin` codec (ordering + `adim_coeff` scaling) survives a Rust encode/decode without drift; property-tested.
3. **Forward parity** - NN forward matches the strict-IEEE harness oracle (real compiled legacy TUs probed against an ascending-loop reimpl; MATLAB's `BLSTM_Forward.m` has divergent semantics and was never the oracle).
4. **Gradient parity** - analytic BPTT matches the same harness oracle bit-exactly plus central finite differences (MATLAB's `BLSTM_Backward.m` shares the divergent semantics; the Python `nn_reference.py` oracle implements ENGINE semantics instead).
5. **Optimizer-step parity** - a single iRPROP- update matches the REAL compiled legacy `Rprop::updateWeights` bit-for-bit, including a fired cost-gated backtrack.
6. **Decision/scoring parity** - segmentation, smoothing, WER/error/LID scoring, EER-cutoff confusion.
7. **End-to-end LID/SAD** - full-pipeline score parity on a held-out corpus.

The flat-weight layout and `adim_coeff` scaling live once in Rust (not duplicated across two languages as in the legacy), so the codec has a single source of truth to validate.

## Oracle tiers

- **Testing (Rust)**: unit tests (inline `#[cfg(test)]`, proptest property tests), integration tests (`src/rust/tests/`). Dev-deps: `approx`, `proptest`, `rstest`, `tempfile`. A `test-support` Cargo feature (self-dev-dep, cfg-gated, absent from the default build) exposes integration-test observation hooks (e.g. per-epoch weight traces, `last_result_rows`) with nothing production-reachable. Validation is golden-file bit-for-bit against the git-ignored `legacy/` oracle, cross-checked via `tools/oracle_harness/` (a local-only strict-IEEE rebuild of vendored legacy sources; CI consumes only the committed fixtures it produces, never builds the harness itself). Since Phase 2 the harness also LINKS the vendored NN translation units (`BLSTMNeuralNetwork`/`LSTMLayer`/`NeuronLayer` + link-only `SRNLayer`/`CWRNNLayer`/`CostLaw`/`Rprop`) and probes the REAL compiled classes against a harness-local ascending-loop reimplementation: NN goldens are dumped from the reimpl, because Eigen's blocked GEMM diverges from ascending accumulation at the k>=23 NN shapes (`manifest.json:nn_product_probes`) and the layer-0 GEMM seeds the recurrence, so the divergence propagates non-locally; NN_TOL probes record the real-class deltas (all synthetic sites 0 ULP; real-net sites small nonzero, kept as Phase 4 calibration data). Bit-exactness holds on the oracle environment (Apple libm; canaries in `tests/reference_data/phase1/libm_canaries.bin`); on other libms (e.g. CI glibc) the transcendental-dependent goldens assert a hybrid bound -- `<= 4` ULP or an absolute tolerance of `512*eps` scaled to the fixture magnitude (libm differences propagate absolutely, so near-zero outputs can be many ULP off) -- canary-gated (`common::oracle_mode`), while the pure-arithmetic goldens stay bit-exact everywhere. NaN fixture elements (the OverLap `0/0` uncovered-row quirk) compare bit-exact on the oracle env but by `is_nan` only off it: the default quiet NaN's SIGN BIT is architecture-defined (x86-64 SSE `0/0` -> `0xfff8...`, AArch64 -> `0x7ff8...`), so a Mac-dumped NaN can never bit-match a CI x86 recomputation. Since Phase 2b the harness additionally LINKS six segmenter translation units (`Segmenter.cpp`, `Segmentation.cpp`, `BLSTMSpectralSegmenter.cpp`, `BLSTMSignalSegmenter.cpp`, `LongTermSpectralVariation.cpp`, `TimeDomainCorrel.cpp`) and upgrades the `iof::fmtr` shim from an inert stub to a FAITHFUL mini-formatter (`%f.Ns` == `std::fixed` + `setprecision(N)`, self-checked per generation via the manifest's `fmtr_shim.checks`), which makes the real compiled `Segmentation::toFile_VRCTS` a byte-golden source in its own right -- closing the Phase 0b-ii VRCTS-writer deferral (see `IMPROVEMENTS.md`). Per-algo goldens follow the SegProbe pattern: harness-local subclasses expose the real protected machinery (`buildFromConf`, `updateSegmentation`, `smoothSegmentation`, `results2segmentation`, the param-derivation family, `getLTSV`, `getBLSTMInputSequence`, `getPitch`, `toFile_VRCTS`) and only the `getSegmentation` bodies are transcribed (NN calls swapped for the bit-stable reimpl family); a SECONDARY real-forward structural probe runs the actual compiled Eigen path per config variant and records segment count/type equality plus boundary-time deltas into the manifest as `SEG_STRUCT` (a structural mismatch aborts fixture generation rather than being silently absorbed -- all landed sites measure `max_dt == 0.0`). VRCTS fixtures embed a fixed synthetic `/tmp` wav path in their AudioDoc attributes (by design, for a stable/reproducible byte golden independent of the local checkout path) -- not a leaked absolute path bug. Since Phase 3 the harness additionally exposes a BACKWARD reimpl family (ascending-loop, mirroring the Phase 2 forward reimpl) with NN_TOL backward probes at synthetic shapes (all landed sites `max_ulp=0`; real-net/output-ratio sites recorded as Phase 4 GEMM-divergence calibration, same non-local blocked-vs-ascending story as the forward), plus two NEW real-compiled-class oracle tiers with no reimpl step at all: `CostLaw::computeUnitaryDeltas`/`computeDeltas` probed directly (polynomial laws bit-exact everywhere, Log/Sqrt canary-gated), and `Rprop::updateWeights` probed directly and asserted STRICT BITS on every platform, no canary gate (pure scalar, no libm/GEMM -- the strongest oracle of the phase). Phase 3 also established a mutation-testing standard for this repo's golden suites: load-bearing quirks (sign conventions, cost-gated branches, count-vs-deriv normalization asymmetries, buffer-reuse across time steps) are paired with an explicit "revert the fix / flip the convention -> the golden must fail" check recorded in IMPROVEMENTS.md, not just a passing assertion. Since Phase 4b the harness additionally links the LID translation units ACTIVELY (`BLSTMSpectralLID.cpp`, `TwinBLSTMSpectralLID.cpp` -- previously link-only, pulled in solely because `BagOfProcessors`' member vectors odr-use their ctors/dtors) via `LidProbe`/`TwinProbe` SegProbe-style subclasses: `getSegmentation` is transcribed, only the NN calls are swapped for the reimpl family, and a SECONDARY real-Eigen `SEG_STRUCT`+`LID_STRUCT` probe aborts fixture generation on any structural mismatch. Two NEW oracle tiers add no reimpl step at all: the Mode-7 phSeq stage pins the REAL COMPILED `getSegmentation` as the oracle directly, since the LID net's one-hot phSeq input makes the layer-0 GEMM summation-free (blocked and ascending accumulation agree bit-for-bit) despite the net's otherwise-divergent k>=23 shapes; and a corpus-level tier runs the REAL compiled `BagOfProcessors`/`TwinBLSTMSpectralLID` drivers, unmodified, over deliberately TINY nets (every GEMM reduction dim < 23, below the divergence threshold), so the corpus fold, `saveAndUpdate`, and Rprop chain are bit-stable end to end. Since Phase 4c the harness FAMILY gains a MATLAB-side sibling, `tools/octave_harness/` (Homebrew Octave 11.3, LOCAL-ONLY exactly like the C++ harness -- CI never installs Octave or runs this harness, it consumes only the committed `tests/reference_data/phase4c/` fixtures the extractor produces): TIER 1 stages run the REAL vendored `.m` classdefs/functions unmodified where they are directly injectable (`SMORMS3.m`, `Rprop.m`, `vec2struct.m`, and `CreateBatches.m`/`CheckGrad.m` behind `addpath`-shadowed dependency stand-ins, e.g. a quadratic surrogate replacing `CostFunction.m`'s engine shell-out), while a FALLBACK tier transcribes only the pure assembly lines with `% legacy:` provenance where a shell-out or self-cleaning step leaves no injection point at all (`ComputeCost.m`'s balance-law assembly, `getCases.m`'s file-local `getWorstAndBest` subfunction). The QuantumPSO oracle is its own SUBSTITUTION-COPY tier: `qpso_modified/QuantumPSO.m` is a near-verbatim copy of the vendored source with ONLY the rand/randperm/stblrnd and cost calls substituted for reads of a shared committed random table (every substitution `% HARNESS-SUB`-commented against the original line), since `QuantumPSO.m:91` reseeds from the wall clock and no single legacy run is reproducible in principle -- the copy pins the OPERATOR STRUCTURE, not a wall-clock trajectory. A genuinely new comparator lesson surfaced here, not a repeat of the Phase 1 libm story: 3 of 8 `ComputeCost` `mean`/`mean(.^2)` cost-scalar goldens sit exactly 1 ULP off Octave even though a plain sequential Python loop reproduces `np.mean` bit-for-bit on every case (ruling out reduction order) -- the gap is Octave accumulating `mean`/`sum` internally in EXTENDED precision (x87/long-double), a loop-order-invariant-in-double effect the usual ascending-loop fix cannot close, so those 3 (`cb3`/`cb4`/`b10a`) stay on the always-tolerant `close` comparator while the 0-ULP cases are promoted to `canary`. Since Phase 4d the harness family gains THREE more local-only, CI-never-run oracle surfaces, every one consumed only via its committed `tests/reference_data/phase4d/` fixtures: (1) `tools/oracle_harness/build.sh --fastmath` builds a SEPARATE binary (`oracle_harness_fastmath`, `-O3 -ffast-math`, every strict-IEEE flag dropped) that deliberately matches the 2015 production binary's FP regime -- the numeric-column (`MultiConfigResults` cost/counter) leg of the parity gate, since the real binary's own FP regime is not bit-matchable even on-host; (2) `tools/fsp_runtime/` resurrects the actual 2015 production `Segment` binary under Rosetta 2 -- it is **Mach-O x86_64** (g++-4.9, `-ffast-math`), NOT Linux ELF as an earlier Phase 4a spec assumed ("the 2015 Linux binary likely does not run on this Darwin/arm64 machine" -- wrong on both counts, corrected here), source-building 6 era-exact x86_64 deps plus a harvested gcc runtime trio and rewiring 9 `/usr/local` install names so it runs unmodified; it is the VRCTS structural/boundary oracle (the binary SIGSEGVs post-inference in the best-weight-save path on a resurrection-only libstdc++ ABI mismatch, tolerated since the VRCTS xml is already written by then); (3) `/usr/bin/perl` running the REAL vendored `.pl` normalizers (`tools/perl_oracle/run_norm.sh`) is the byte-oracle for `stm_normalize.py`'s light-normalizer path. Octave gained two new stages too -- `stage_writelisting.m` (TIER 1, the real `WriteListing.m`/`WriteWeightedListing.m` unmodified) and `stage_scr.m` (HYBRID: a real Tier-1 `processListing.m` call plus a fallback-transcribed `.scr`-writer loop) -- same local-only posture as the rest of the family. None of the three new surfaces ever run in CI.
- **Testing (Python)**: pytest, hypothesis (property-based). Golden reference fixtures under `tests/reference_data/`, added per roadmap phase. Round-trip property tests are mandatory for the weight bridge.

## Standing gates, by the phase that introduced them

- **Since Phase 5**: goldens assert PORT-TRUTH, not legacy-truth -- Roadmap 2 tasks deliberately FIX legacy bugs (F1-F11 landed; see IMPROVEMENTS.md's `[phase5]`-tagged entries) instead of reproducing them bit-exactly, the inverse of the Roadmap-1-era "do not fix mid-port" rule ([ADR-0001](adr/0001-port-truth-after-the-parity-tag.md)). Every fix follows IMPROVEMENTS.md's "Phase 5 fix protocol" (RED -> re-pin -> mutation -> flip the entry to `FIXED (phase 5, F<n>, commit <hash>)`), so a fixed entry keeps its original legacy-behavior description for the record. The C++/Octave/Perl/resurrected-binary oracle harness family (`tools/oracle_harness/`, `tools/octave_harness/`, `tools/perl_oracle/`, `tools/fsp_runtime/`) is NOT regenerated for fixed sites and is never a Phase-5+ correctness target -- each fix's IMPROVEMENTS entry documents the now-deliberate divergence; the harnesses describe the LEGACY only, forever, and stay useful exclusively as Roadmap-1 provenance and as the oracle for entries the sweep left kept-documented.
- **Since Phase 6 (corpus-gating)**: real-data tests are CORPUS-GATED and LOCAL-ONLY -- every test that touches `data/LRE03-LRE07/` (the 27 GB gitignored licensed corpus) or `data/Scoring_LRE15/` is guarded by `requires_corpus`/`CORPUS_ROOT` (Python, `tests/conftest.py`) or `common::corpus_root_or_skip` (Rust, `src/rust/tests/common/mod.rs`) and SKIPS cleanly when the corpus is absent, so CI (which never has it) runs only SYNTHETIC committed fixtures (the 8 hand-crafted cep binaries under `tests/reference_data/phase6/cep/`, the 14 crafted DCF goldens the perl produced, the listing/localization fixtures with synthetic names). LICENSE HYGIENE is a hard rule: no corpus path, filename, or feature table is committed anywhere -- fixtures and docstrings use synthetic pattern-preserving names, and the arm configs carry runtime placeholder listing keys the drivers rewrite. Since 2026-10-02 the rule is executable: `tests/test_license_hygiene.py` scans every tracked text file (a symlink as its target path) for a concrete filename on a path through the corpus root directory (directory globs and the bare root pass; bare basenames, binaries and the 2015 host-prefixed listing paths stay review-only) and pins that the launcher's `runs/` output directory is gitignored (#31). The new oracle surfaces (`/usr/bin/perl` running `scoreFile_SAD.pl` v2.1 for `dcf`, and the LRE15 `ComputeCavgNIST.py` cross-check for `cavg`) are local-only like the rest of the harness family, consumed in CI only via their committed goldens. A Phase-6 mutation battery (Task 11) broke 8/8 targeted mutations against their named catchers (four honest single-catcher/corpus-gated coverage gaps recorded, no un-caught mutation).
- **Since Phase 7 (two inference trees)**: the repo now carries the behavior-untouched exact f64 path (goldens byte-stable) AND a runtime-selectable f32 `fast/` path (`Inference_Path`). The standing drift detector is the fast-vs-exact PARITY GATES -- `phase7_parity_{sad,lid}.rs` on committed fixtures (CI-visible) + `tests/pyo3/test_phase7_parity.py` (corpus-gated) -- which assert boundary/argmax IDENTITY and metric deltas EXACTLY 0.0, so any f32 divergence that would move a decision fails loudly (spec R1: STOP-and-adjudicate, never silently widen). PRECISION NOTE (found phase-11 Task 6 review, F3): "boundary/argmax IDENTITY" names both gates together, but the two tiers own DIFFERENT halves -- the SAD tier's decision gate is boundary count/type + `max_dt == 0.0` (argmax is VACUOUS-BY-SHAPE there, `OutputNeuronNb` collapsing to a single class so argmax is a constant 0), and the argmax-zero-flips gate lives in the LID tier (`phase7_parity_lid.rs`) alone; a new cell's SAD parity leg should not expect an argmax assertion to be doing any work. The exact tree stays FROZEN: fast-path numeric divergence is BY DESIGN (spec S4), documented in the `fast/` module docs + `RESULTS.md` and NEVER `IMPROVEMENTS.md` (which tracks legacy-quirk debt only) -- the sole sanctioned exact-tree touches are the five behavior-free classes named in the Phase 7 roadmap bullet (bench plumbing, the dispatch site + key row, the two training/seam guards, the golden-re-verified hoists). Benchmarks follow measure-then-pin: a WIDE CI budget smoke (`fast wall <= exact*1.5`) plus local this-box regression bounds, the real numbers local and hardware-named (`RESULTS.md`). A Phase-7 mutation battery (Task 10) ran 8/8 (six direct catches + two honest recorded gaps: the designed hoist-neutrality no-op, and a frozen-SAD coverage boundary proven non-vacuous by a faithful variant).
- **Since Phase 8 (streaming)**: the repo now carries a stateful chunked-input streaming path (`fast/stream.rs` SAD + `fast/stream_lid.rs` LID) beside the offline fast tree, INFERENCE-ONLY + MONO-first, the numeric heart being the phase-7 f32 kernels UNTOUCHED. The standing drift detectors are the STREAMING BIT-EQUAL CONTRACTS -- `phase8_gate.rs` (streamed `finish` == the offline-frozen fast bag: boundary max_dt EXACTLY 0.0 + posterior history bit-identical, BOTH configs) + `phase8_stream_lid.rs` (per-utterance/finish/prefix bit-identical to the offline Twin) on committed fixtures (CI-visible), lifted onto real corpus data by `tests/pyo3/test_phase8_parity.py` (corpus-gated) -- so any streaming divergence that would move a decision fails LOUDLY (R1: STOP-and-adjudicate, never silently widen). The design's ONE new safety invariant is the CONSUMED-FRONTIER emission trigger: `StreamDecision` emits a settled prefix keyed off `consumed_frontier - dt` (the frontier the hysteresis has actually CONSUMED), NEVER the merely-received frontier -- delivering the speech-class bounded latency without a premature (retractable) emission; the derived `holdback` conservatively dominates the true smoothing reach, and the prefix-consistency gate catches a too-small holdback as a retraction (R2). SINCE PHASE 9 TASK 9 the trigger carries a THIRD term, `hyst.pending_begin()` (an OPEN, not-yet-closed raw segment begins BEHIND the consumed frontier, so the first two terms do not bound it): without it a speech segment reopening within the holdback merges back through `add_padding` and MOVES an already-emitted boundary -- a real R2 retraction that only REAL corpus data with a trained causal net exposed (the whole committed fixture suite stays green under the reverted clamp), which is why the corpus tiers exist. Frozen-norm (`Audio_fixed_gain` + the pack-carried type-1 tail) is the causality cut -- it replaces the two whole-file statistics, not the arithmetic.
- **Since Phase 9 (the cell axis)**: the repo now carries a THIRD axis beside exact/fast and offline/streaming -- the recurrent CELL (`nn/cells/` exact f64, `fast/cells.rs` f32 causal) -- and `CellLayer` is the STANDING EXTENSION SEAM: a new architecture is a new enum variant plus a `Layer` impl, an `init_weights.py` builder emitting the same flat order, and its `KEY_TABLE` rows. Nothing outside those three places should need to change (a fast/causal twin additionally needs a `fast/cells.rs`/`fast/bicell.rs` kernel; `classify_fast_shape`'s match is generic over `CellType`, so -- as of Phase 10 -- it does NOT need a new arm per cell, a finding Phase 11's transformer landing confirmed and this same commit records twice elsewhere), and the exhaustive `match cell_type` in `BlstmNetwork::from_config` makes forgetting one a COMPILE error. TWO standing rules follow. (1) THE EXACT-TREE DISCIPLINE (spec S1.4/R2): a new cell adds code inside `cells/`; any diff to `nn/` OUTSIDE `cells/` must be justified in review against the sanctioned classes -- THREE named at phase-9 open (the enum wrap, the `Direction` forward-only branches, the `KEY_TABLE` rows), a FOURTH added phase-10 Task 9 (the `set_retain_cache` retention arm), and a FIFTH added at the phase-11 interstitial (`BlstmNetwork::set_weights`'s EXACT-length guard, closing a pre-existing over-long-pack hole every cell shared; see the `nn/blstm.rs` row) -- with the committed golden suite byte-green as the only acceptable proof. Port-only numeric divergence of the new cells is BY DESIGN and belongs in module docs + `RESULTS.md`, NEVER `IMPROVEMENTS.md` (the phase-7 rule, unchanged). (2) THE BATTERY LESSON (Task 10, the phase's sharpest epistemic result, recorded because it is easy to get backwards): every SELF-CONSISTENT leg -- split-state bit-identity, chunk-invariance, the whole streaming gate -- compares TWO RUNS OF THE SAME KERNEL, so it is STRUCTURALLY BLIND to any mutation applied inside that kernel. Those legs pin state THREADING; the ARITHMETIC is pinned by the fast-vs-exact parity legs and the exact-cell FD/unit tier. That is the correct division of labour, but it means a passing streaming gate is NOT evidence a cell computes the right thing, and a new cell needs BOTH tiers before it is trusted. **SHARPENED BY THE PHASE-10 BATTERY (T11 item 6), because "parity owns arithmetic" was too generous:** the parity legs own DECISIONS unconditionally, but they own ARITHMETIC only AT THEIR PIN'S RESOLUTION. A SYMMETRIC kernel substitution -- one applied inside the shared `step` both sides drive -- is invisible to self-consistency by construction AND sits under any measured*10 pin (measured: a batched-projection swap inside `FastLstm::step` moved the drift 4.4019e-7 -> 4.9980e-7, 1.14x, against a 1e-4 pin sized for cross-platform SIMD variance), so sub-pin kernel-substitution arithmetic is owned by NOTHING -- deliberately, since the fast tree has no bit-exact oracle to own it with. THREE CONSEQUENCES, all load-bearing. (a) The control is a DESIGN-TIME rule, not a test: `fast/cells.rs`'s divergence 2 (every projection a per-step `dot_f32` over a contiguous weight row) forbids exactly that edit, in the module doc of the file it would be made in -- so review the RULE, do not expect a leg to catch its violation. (b) The ASYMMETRIC version, which is the shape a real performance edit takes, IS caught: batch one side only and the streaming bit-identity legs fire. (c) "Impossible to catch" is really "DECLINED": a same-precision f32 SELF-golden would catch it, at the cost of pinning the host's SIMD lowering and needing phase-1-style canary gating.
- **Since Phase 10 (the completed fast matrix + the v2 lineage)**: TWO standing facts. (1) THE (cell x direction) FAST MATRIX IS TOTAL and that is now an INVARIANT, not a milestone: `fast::driver::classify_fast_shape` returns a `FastNetShape` with no `Result`, so every `(cell, direction)` pair the exact tree can build has an f32 twin -- bidirectional-LSTM `FastBlstm`, bidirectional-{slstm, mamba, cfc, transformer} `FastBiCell`, causal-{lstm, slstm, mamba, cfc, transformer} `FastCausalNet` (PHASE 11 EXTENDED THE SET TO FIVE CELLS AND THE INVARIANT HELD: `classify_fast_shape`'s match stayed generic over `CellType`, so `transformer` needed no new arm in the classifier itself, only its own kernels in `fast/cells.rs`/`fast/bicell.rs`). A NEW CELL must therefore land BOTH twins (or a deliberate, documented, test-pinned bail) in the same phase it lands its exact cell, and forgetting is a COMPILE error at `cell_weight_count`'s exhaustive match rather than a runtime surprise -- which is strictly stronger than the phase-9 bail regime it replaces, because before the totalization an over-long pack under the wrong cell name was consumed head-first and RAN. What stays out of the matrix by CONSTRUCTION, not by omission: bidirectional STREAMING (the reverse stack's state at `t` depends on samples after `t`, so no bounded lookahead makes it causal) and TRAINING on the fast path (exact f64 only, loudly bailed). (2) TWO SAD LINEAGES NOW EXIST AND THEY ARE NOT INTERCHANGEABLE: `lre_sad.toml` (v1) is the ONLY 2015-capacity-comparable one -- its 33671 LSTM pack IS the production tuple-A size and the phase-6 baseline numbers are its -- while `lre_sad_v2.toml` is a NEW lineage with no 2015 counterpart, differing in exactly two value lines. Their LIVE parameter counts are IDENTICAL per cell (the fork removes only structurally-dead weight), so any v1-vs-v2 comparison is about pack size and init scaling, never capacity; quote the lineage whenever a SAD number is quoted, and keep v1's gates FROZEN when touching v2's.
- **Since the ledger (issue #20, ADR-0009)**: every number a RESULTS.md ledger table quotes is a RECORD under `ledger/<kind>/<id>.json` (an envelope of schema version, UTC time, git SHA + dirty flag, `speech_rs.build_info()` and the host's hardware class around a `recipe`, the measurement's identity, and a `payload`, its metrics). Producers write where they run (`run_baseline` -> `record.json`; a subset gate overwrites it with `source=gate` and its node id, staged out of `tmp_path` by `pytest --ledger-stage`; `speech bench --json` prints the bench payload); the ONE way into the committed tree is `python -m speech.ledger add`, which validates the schema and the license-hygiene rule (no corpus file, no absolute path, in any string field), refuses a dirty-tree record without `--allow-dirty` and a non-release build always, then renders. The tables between `<!-- ledger:table <name> -->` / `<!-- ledger:end -->` are rewritten by named renderers (`speech.ledger.tables`) and CI asserts RESULTS.md holds exactly that rendering (`tests/test_ledger.py`). The record is NOT the pin (ADR-0003's pins stay in the tests); supersession is append-only (`supersedes` + `reason`, the old row hidden and footnoted); no historic number was transcribed, every gate was re-run on `main` to produce its record, and a re-run metric that differs from the printed value is a STOP.
