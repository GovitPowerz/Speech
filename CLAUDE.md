## Project Overview

Speech is a port of the legacy `FastSpeechProcessing` system: a fast forward+gradient engine for Speech Activity Detection (SAD) and spoken Language Identification (LID). The original splits across two languages -- a C++ engine (~21.5k LOC of logic plus a 200k-line `Constants.h` data table) that does audio I/O, acoustic feature extraction (FFT periodogram, Mel/MFCC/deltas/SDC, LTSV, time-domain pitch), from-scratch bidirectional recurrent nets (peephole BLSTM, SRN, Clockwork-RNN) + output MLP, analytic BPTT gradients, an in-engine iRPROP- update, SAD segmentation, and a TwinBLSTM LID head that consumes the SAD net's hidden states; and a MATLAB `Optimizer_V6.2.2` (110 `.m` files) that runs the outer optimization loop -- global DSP-hyperparameter search (bespoke QuantumPSO or CMA-ES) plus gradient NN training (SMORMS3 and friends), cross-entropy losses, calibration cost laws, EER-cutoff confusion scoring, and hard-example mini-batching. The port maps the C++ engine to **Rust** (crate + binary `speech`) and the MATLAB optimizer to **Python** (package `speech`). The legacy seam is a file/subprocess boundary -- a flat `.config`, little-endian `.bin` weight/gradient vectors, `fileslisting`/`language2classmapping` CSVs, and `.mat` results, with the engine launched per evaluation via `RunFsp.py`. This repo replaces that seam with an **in-process PyO3 API** (`speech-py` -> module `speech_rs`) for the hot training loop, while keeping the legacy formats as a byte-compatible serialization layer for validation and cluster drop-in. The flat-weight layout and `adim_coeff` scaling live **once** in Rust (`io::binary` + `nn`) exposed to Python, not duplicated across two languages as in the legacy. The parity target is bit-exact-where-feasible against the legacy oracle: the roadmap led with a pure-logic + I/O layer (config parser, weight `.bin` codec, segmentation/smoothing/scoring, features) golden-tested bit-for-bit before any NN landed. The phases marked done in the Roadmap / architecture table (pure logic + I/O, features, NN forward, per-file SAD segmenter drivers, network-level training, the Phase 4a corpus/engine drivers + CLI, the Phase 4b LID head -- Algo 5/6 TwinBLSTM + the VRCTS adapter + the live corpus LID arms, the Phase 4c PyO3 seam + Python optimizer/orchestrator -- `speech_rs.Engine`, the TOML canonical config, the Octave-pinned optimizer zoo, the vec2struct genome bijection, the cost/gradient seam, and the `init`/`train`/`retrain`/`test` lifecycle drivers, and the Phase 4d dataprep + end-to-end closeout -- `dataprep/` (augmentation, NIST OpenSAD15 conversion, STM normalization, listing writers), both deferred parity milestones executed against the resurrected 2015 `-ffast-math` production binary (VRCTS byte-identical structurally and per-boundary, scored `MultiConfigResults` columns within a max relative delta of ~1e-15), the Phase 0a packer/adim byte golden closed against two real 2015 weight packs, the feasible backlog four (algo-3 driver generalization, live batch-mode training, the `.scr` Octave golden + alphabetical class-order fix, the Phase 4c Task 8 mask-vector debt closure), and four permanently-blocked-but-typed-and-pinned closures (the WER shell-out cost balances 6-9, the Twin's reference-based pitch second pass, the Mode-7 WAV/CNN arm, and cep `File_Type` 2+ ingestion -- this last since RE-OPENED and closed by Phase 6 Task 1, which landed the real `File_Type 2` cep reader against the LRE03/07 corpus, so only `File_Type 3/4` stay bailed)) are real, tested logic. **The Rust engine and the Python side are both complete through Phase 4d; no stub remains anywhere in `src/rust/src/` or `src/python/speech/`, and the roadmap is DONE.**

**Roadmap 1 (the port era) is closed and tagged.** The parity proof above -- bit/tolerance-exact against the resurrected 2015 `-ffast-math` production binary -- is frozen as the annotated tag `legacy-parity-v1` (`main@74284d6`, the Phase 4d merge commit); `git checkout legacy-parity-v1` reproduces it exactly, gates included. The 2015-parity gates (`src/rust/tests/phase4d_parity.rs`, `tests/test_phase4d_parity.py`) are DELETED from HEAD (not skipped or `#[ignore]`d) in the same commit that creates the tag -- they only ever asserted legacy-truth, which is no longer the target. ## Architecture

The Rust crate (`src/rust/`) is the engine: a Cargo workspace with the core `speech` crate (lib + bin) and the `speech-py` PyO3 binding crate (module `speech_rs`). TOML is the canonical config; a legacy `.config` importer exists for validation runs against goldens. The Python package (`src/python/speech/`) is the optimizer and orchestrator, driving the engine in-process via PyO3.

## Key Decisions & Pitfalls

### Locked decisions

- **Naming**: Rust core crate `speech` (lib + bin), PyO3 crate `speech-py` -> module `speech_rs`, Python package `speech`, CLI binary `speech`. Mirrors the sibling `aerocapture`/`aerocapture-py`/`aerocapture_rs`.
- **Legacy source**: vendored source-only under `legacy/` (C++ `src/` + `Optimizer_V6.2.2` `.m`, no data/figures/executables). `legacy/` is **git-ignored** -- present locally as a golden oracle, not committed.
- **Config format**: **TOML is the canonical config path** (Phase 4c, `toml_config.rs`): a 177-entry `KEY_TABLE` (the Phase 4c 175 + the port-only `Inference_Path` (Phase 7) and `Audio_fixed_gain` (Phase 8)) declaratively flattens every `[section]` key the committed fixture configs use to/from the legacy flat-key shape off ONE bidirectional table (both directions read the same table, so encode/decode cannot drift apart); an unmapped key round-trips losslessly through `[legacy.raw]` (no key is ever silently dropped); `speech --convert-config in.config out.toml` (a port-only CLI addition, doc-commented as such) converts, and both the CLI and the PyO3 `Engine`/`load_toml_config` accept `.toml` by extension. The legacy `.config` importer (`legacy_config.rs`) is RETAINED, not superseded -- it stays the golden-validation path (parity runs against the real legacy fixture configs) and `.config` is still accepted everywhere `.toml` is. Phase 7 added the port-only `Inference_Path` key to the `KEY_TABLE` (`[engine] inference_path`, default `exact`; `fast` selects the f32 fast-inference drivers) -- see the `engine/bag_of_processors.rs` row. Phase 8 added the port-only `Audio_fixed_gain` key (`[audio] fixed_gain`, no C++ source): when present it replaces the whole-file `(2*RMS+max)/2` audio normalization with a frozen constant (the streaming causality-cut reference gain, `audio.rs::apply_fixed_gain` + `fast/stream.rs`). GAIN-INERTNESS FINDING (T1 fix-wave): on an all-DCT / `IgnoreFirstDCT` config (like tier2) a uniform per-file log-shift is annihilated by the AC DCT basis + the temporal deltas, so ANY positive `Audio_fixed_gain` yields the SAME posterior -- posterior-INERT (proven algebraically AND empirically 0.0-delta over 1500 rows); the gain is only decision-relevant for raw-band / mel-input configs.
- **Roadmap order**: lead with the **pure-logic + I/O parity layer** (config parser, weight `.bin` codec, segmentation/smoothing/scoring, feature extraction), golden-tested bit-for-bit before any NN.
- **Phase 0a status (complete)**: the `.bin` codec is byte-exact-validated against the real `NNweights_config1.bin`, and the legacy `.config` parser against the real `1_worker_1.config`. The `adim_coeff` seam + flat weight packer is validated by source cross-check vs `config2weights.m`, the exact element count (33,671), the mutual-inverse bijection, adim invariants, the normalize-tail matching a real `.bin`, and Rust-pack == Python-pack cross-language agreement -- it was NOT validated against an independent legacy golden pack at the time, because none existed (`nnet_best` is the CMA-ES optimizer genome, not a weight-pack). **CLOSED in Phase 4d Task 1**: two real 2015 production weight packs repack BYTE-IDENTICAL, file-level (stronger than the Phase 0a vector-level check) -- tuple A (33,671 elements, byte-identical to the Phase 0a fixture, disclosed as the SAME production run) and, genuinely independently, tuple B (a V6.2.1 net, `NNetInputSize=35`, 42,911 elements, an architecture no prior fixture covered). Classic RED was infeasible (no independent structured<->`.bin` pair to mutate against), so the closure used MUTATION PROBES instead (a weight flip breaks identity repack; a spec-field corruption changes the decoded element count from 22,751 to 42,911), independently reproduced by the review.

### Parity hazards (port carefully, golden-test each)

- **Weight-vector flat layout ordering**: input/recurrent gate blocks, then the 12-row peephole bundle, then 4 biases, then the mean/std tail. Get the ordering wrong and every downstream number is garbage.
- **`adim_coeff` scaling**: `adim_coeff = sqrt(fan_in*sub + fan_out)`, bias-excepted. In the legacy this scaling lives **only in the config reader**, NOT in the flat packer -- so a naive round-trip through the packer drops it. In this port it must live once in Rust.
- **CellWeight-narrow layout**: unlike the Input/Forget/Output gate matrices, the Cell matrix carries no peepholes -- its rows are `out + in + 1` (recurrent + fan-in + bias only), one column-triplet shorter than the gate matrices. Easy to over-generalize and get wrong.
- **Activations**: non-standard. `Maxmin2`/`Identity` are `asinh` (cell + output), `GatesFunction` is `sigmoid(0.1z)` (note the 0.1 pre-scale), output is softmax.
- **iRPROP- inverted sign convention**: the legacy update uses an inverted sign; copy it exactly, do not "fix" it.
- **FFT two-real packing + custom Welch normalization**: two real signals packed into one complex FFT, with a bespoke normalization -- not the textbook periodogram.
- **Non-standard LTSV**: score is `-sum r(r-1)`, and it uses variance, NOT its square root.
- **Fixed 100000-entry random tables**: `Constants.h` bakes in two 100000-entry random tables for determinism; reproduce them (and the modular indexing) faithfully.
- **Little-endian assumption**: `.bin` and `.mat` are little-endian; the codec hard-assumes LE.
- **Layer naming off-by-one**: MATLAB is 1-based, the config `Layer_%d` keys are 0-based. Mind the offset when bridging.
- **In-band signaling offsets**: `score > 150` and `val - 200` encode signals in-band in the legacy numeric streams; these magic offsets are load-bearing, not noise.

Legacy bugs/oddities are reproduced bit-exactly on purpose (they are load-bearing for the goldens) and tracked in **[IMPROVEMENTS.md](IMPROVEMENTS.md)** to revisit after end-to-end parity.
