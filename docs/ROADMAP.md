# Roadmap

Two roadmaps, phase by phase: what each delivered, what it proved, and what it left named. Each phase has a dated design spec and implementation plan ([docs/superpowers/](superpowers/README.md)), its numbers in [RESULTS.md](../RESULTS.md), and its reproduced-or-fixed legacy behaviours in [IMPROVEMENTS.md](../IMPROVEMENTS.md). Every phase listed here is done and merged; the one open item is the user-fired full-corpus runs whose numbers [RESULTS.md](../RESULTS.md) receives as they complete.

## Where the port stands

Speech is a port of the legacy `FastSpeechProcessing` system: a fast forward+gradient engine for Speech Activity Detection (SAD) and spoken Language Identification (LID). The original splits across two languages -- a C++ engine (~21.5k LOC of logic plus a 200k-line `Constants.h` data table) that does audio I/O, acoustic feature extraction (FFT periodogram, Mel/MFCC/deltas/SDC, LTSV, time-domain pitch), from-scratch bidirectional recurrent nets (peephole BLSTM, SRN, Clockwork-RNN) + output MLP, analytic BPTT gradients, an in-engine iRPROP- update, SAD segmentation, and a TwinBLSTM LID head that consumes the SAD net's hidden states; and a MATLAB `Optimizer_V6.2.2` (110 `.m` files) that runs the outer optimization loop -- global DSP-hyperparameter search (bespoke QuantumPSO or CMA-ES) plus gradient NN training (SMORMS3 and friends), cross-entropy losses, calibration cost laws, EER-cutoff confusion scoring, and hard-example mini-batching. The port maps the C++ engine to **Rust** (crate + binary `speech`) and the MATLAB optimizer to **Python** (package `speech`). The legacy seam is a file/subprocess boundary -- a flat `.config`, little-endian `.bin` weight/gradient vectors, `fileslisting`/`language2classmapping` CSVs, and `.mat` results, with the engine launched per evaluation via `RunFsp.py`. This repo replaces that seam with an **in-process PyO3 API** (`speech-py` -> module `speech_rs`) for the hot training loop, while keeping the legacy formats as a byte-compatible serialization layer for validation and cluster drop-in. The flat-weight layout and `adim_coeff` scaling live **once** in Rust (`io::binary` + `nn`) exposed to Python, not duplicated across two languages as in the legacy. The parity target is bit-exact-where-feasible against the legacy oracle: the roadmap led with a pure-logic + I/O layer (config parser, weight `.bin` codec, segmentation/smoothing/scoring, features) golden-tested bit-for-bit before any NN landed. The phases marked done below (pure logic + I/O, features, NN forward, per-file SAD segmenter drivers, network-level training, the Phase 4a corpus/engine drivers + CLI, the Phase 4b LID head -- Algo 5/6 TwinBLSTM + the VRCTS adapter + the live corpus LID arms, the Phase 4c PyO3 seam + Python optimizer/orchestrator -- `speech_rs.Engine`, the TOML canonical config, the Octave-pinned optimizer zoo, the vec2struct genome bijection, the cost/gradient seam, and the `init`/`train`/`retrain`/`test` lifecycle drivers, and the Phase 4d dataprep + end-to-end closeout -- `dataprep/` (augmentation, NIST OpenSAD15 conversion, STM normalization, listing writers), both deferred parity milestones executed against the resurrected 2015 `-ffast-math` production binary (VRCTS byte-identical structurally and per-boundary, scored `MultiConfigResults` columns within a max relative delta of ~1e-15), the Phase 0a packer/adim byte golden closed against two real 2015 weight packs, the feasible backlog four (algo-3 driver generalization, live batch-mode training, the `.scr` Octave golden + alphabetical class-order fix, the Phase 4c Task 8 mask-vector debt closure), and four permanently-blocked-but-typed-and-pinned closures (the WER shell-out cost balances 6-9, the Twin's reference-based pitch second pass, the Mode-7 WAV/CNN arm, and cep `File_Type` 2+ ingestion -- this last since RE-OPENED and closed by Phase 6 Task 1, which landed the real `File_Type 2` cep reader against the LRE03/07 corpus, so only `File_Type 3/4` stay bailed)) are real, tested logic. **The Rust engine and the Python side are both complete through Phase 4d; no stub remains anywhere in `src/rust/src/` or `src/python/speech/`, and the roadmap is DONE.**

**Roadmap 1 (the port era) is closed and tagged.** The parity proof above -- bit/tolerance-exact against the resurrected 2015 `-ffast-math` production binary -- is frozen as the annotated tag `legacy-parity-v1` (`main@74284d6`, the Phase 4d merge commit); `git checkout legacy-parity-v1` reproduces it exactly, gates included. Starting Phase 5, HEAD opens **Roadmap 2** (see below): the golden regime flips from LEGACY-TRUTH to PORT-TRUTH, because Roadmap 2 tasks deliberately fix legacy bugs instead of reproducing them bit-exactly. The 2015-parity gates (`src/rust/tests/phase4d_parity.rs`, `tests/test_phase4d_parity.py`) are DELETED from HEAD (not skipped or `#[ignore]`d) in the same commit that creates the tag -- they only ever asserted legacy-truth, which is no longer the target. Every fixture under `tests/reference_data/phase4d/` stays (the packer golden, the algo-3 smokes, and `tests/test_phase4d_fixtures.py`'s integrity guards still consume it), and the local-only oracle family that produced the parity fixtures (`tools/fsp_runtime/`, `tools/oracle_harness/ --fastmath`) is untouched. See `IMPROVEMENTS.md`'s "Phase 5 fix protocol" preamble for the per-fix RED -> re-pin -> mutation -> flip procedure every un-quirk task now follows.

## Roadmap 1: the port (phases 0a to 4d, closed at tag `legacy-parity-v1`)

The port lands in phases, leading with the lowest-risk, highest-leverage layer (pure logic + I/O) so everything downstream stands on golden-tested ground.

- **Phase 0 - pure-logic + I/O parity (first).**
  - **Phase 0a - byte-parity foundation (done).** The `io::binary` `.bin` codec and the `legacy_config`/`config_bridge` parser are golden-tested bit-for-bit against the real `NNweights_config1.bin` and `1_worker_1.config`. The `config`/`weight_bridge` adim seam + flat weight packer is cross-language-validated (Rust-pack == Python-pack) and source-verified against `config2weights.m` (element count, bijection, adim invariants, normalize-tail vs a real `.bin`); an independent legacy golden pack does not exist yet (`nnet_best` is a CMA-ES genome, not a weight-pack), so the end-to-end bit-exact packer/adim golden is deferred to the end-to-end inference-output parity milestone (inference on a real `.bin` matched against the legacy VRCTS segmentations; see Phase 4 below). **This deferral was CLOSED in Phase 4d Task 1** -- see below -- against two real 2015 production weight packs, byte-identical file-level.
  - **Phase 0b-i - cost laws + Segmentation container (done).** `cost.rs` ports the 7 piecewise VAD cost laws (linear/square/cubic/log/sqrt, below+above-threshold) plus the multiclass softmax cross-entropy; the scalar VAD path is golden-tested bit-for-bit against the legacy `test_costlaws.mat` (linear law, `CostPonderation=0.2`), while the other laws and the softmax path are unit-tested from the exact `CostLaw.{h,cpp}` coefficients (no external `.mat` golden for those yet). `tasks::segmentation` ports the boundary-list `Segmentation` container (`SegClass`/`Segment`, `label_segment`/`sanitize`/`suppress_short`/`add_padding`/`modify_type`/`update_count`), unit-tested against hand-derived boundary lists plus a `sanitize` proptest; no external golden yet (segmentation-output goldens land in 0b-ii via VRCTS XML).
  - **Phase 0b-ii - segmenter decision logic + scoring (done).** `tasks::segmenter` ports the decision primitives (`update_segmentation` hysteresis-with-area over a row vector, `lid_to_segmentation` single-threshold over a column vector, the fixed 8-step `smooth_segmentation`, `get_targets`); `tasks::segmentation_io` ports the VRCTS XML writer/loader, the STM/CSV reference loaders, the ASCII writer, and `compute_errors` (per-class Pfa/Pmiss/ErrorRate Pass 2 plus the WER/coverage/delay pass). Validation: the VRCTS loader round-trips byte-exact against the real fixtures and the writer is pinned by a constructed 4-decimal (`%f.4s`) golden (at this point the committed fixtures were external `vrcts_part` reference input, so the writer-vs-real-engine byte golden deferred; **this deferral was CLOSED in Phase 2b** -- see below -- once a faithful in-harness formatter made the real compiled writer itself a byte-golden source); the segmenter decision and `compute_errors` Pass 2 are hand-computed-unit-tested **and** cross-checked bit-for-bit against a numpy differential oracle (Rust == Python); WER (Pass 1/3) is unit-tested only (no `.csv` reference in the tree yet). This **closes the Phase 0/0b pure-logic + I/O parity layer** -- next is Phase 1 (features).
- **Phase 1 - features (done).** Audio I/O, FFT, Mel/MFCC/deltas/SDC, LTSV, TDC, streaming stats, and feature-pipeline param derivation/assembly, golden-tested bit-for-bit against a strict-IEEE oracle harness (`tools/oracle_harness/`: vendored legacy sources rebuilt with Homebrew g++, `-O2 -std=gnu++14 -fpermissive -fno-fast-math -ffp-contract=off -DEIGEN_DONT_VECTORIZE`, no OpenMP -- a deliberate deviation from the original `fsp` binary's `-ffast-math`/gcc-4.9 build; comparing against that original binary's tolerance is deferred to Phase 4). Bit-exactness is the contract on the oracle environment (Apple libm; libm canaries recorded in the fixtures as `libm_canaries.bin`); on other libms the transcendental-dependent goldens (cos/ln/exp chains) assert a hybrid bound instead of exact bits -- `<= 4` ULP or an absolute tolerance of `512*eps` scaled to the fixture magnitude (a 1-ULP libm difference propagates as an absolute error, so near-zero outputs like a Hann window tail can be many ULP off) -- canary-gated, so CI on glibc stays green without weakening the pure-arithmetic goldens. The **end-to-end feature parity gate** (`phase1_pipeline_golden.rs`) reproduces the full legacy chain -- excerpt -> pre-emphasis -> windowing -> periodogram -> mel/DCT per config -> LTSV -> `assemble_input_sequence` -- bit-exact vs `inputseq_<variant>_chan{1,2}.bin` across 4 config variants (mfcc+deltas, mfcc+SDC, log-mel, raw-band+LTSV) x 2 channels. `features/fft.rs` is an EXACT GFFT port (Taylor-twiddle-seeded radix-2 DIT + Numerical-Recipes running recurrence, the DL&lt;4&gt; fused `-i` butterfly, 1-based NR bit-reversal) -- `rustfft`/`realfft` are NOT used on this exact path (library FFTs cannot match the oracle's exact rounding; as of Phase 7 `realfft` powers the separate f32 fast path and the direct `rustfft` declaration is dropped). One real divergence surfaced and was absorbed rather than hidden: the mandatory Task-7 harness pre-check found Eigen's scalar GEMM for the DCT projection (`melPeriodogram * _CoeffsDCT`) does not accumulate in ascending order even fully devectorized (measured: 1511/2613 elements ~1 ULP off an explicit ascending loop), so both the harness and `features/mel.rs` use the explicit ascending-loop product as the portable parity target (`manifest.json:dct_gemm_substitution`) -- DCT-path goldens are therefore ~1 ULP off a hypothetical real-Eigen legacy run, an acceptable/expected gap absorbed by Phase 4. Provenance varies by module: `audio.rs`/`features/{fft,mel,stats}.rs` are pinned against COMPILED legacy translation units linked into the harness (`AudioStruct`, `MelFilterBank` construction + filter-bank apply, `InputStatistics`); `features/ltsv_tdc.rs` and the pipeline's param-derivation/assembly logic are pinned against a diff-reviewed VERBATIM TRANSCRIPTION in the harness (the LTSV/TDC classes can't compile standalone -- they drag in the whole `Segmenter` hierarchy), cross-checked by numpy oracles independent of the harness; symphonia's WAV decode was verified bit-exact against libsndfile (PCM16 x/32768) and is pinned by the `sig_norm.bin` harness dump golden (`decode_normalize_matches_oracle`, `phase1_audio_golden.rs`). See `IMPROVEMENTS.md` for every reproduced legacy quirk (dropped N+1th window sample, DC-bin `/n` vs AC `/4n` periodogram normalization, odd-tail double write, `get_sequence` stale-buffer/no-op/DC-offset-over-padding, unnormalized-uniform-window fallthrough, `round(rate*dur+1)` clip length, convolution edge truncation without renormalization, LTSV variance-not-std, `[delta|delta|dd]` static overwrite, SDC `ignoreFirst` last-static clobber, `fmath_log` finite at 0, `InputStatistics` std-resqrt merge order, and more) -- none of them were "fixed" mid-port; they are load-bearing for the goldens.
- **Phase 2 - NN forward (done).** `nn/{activations,layers,network,blstm}.rs`: the exact activation overrides (asinh cell/output, `sigmoid(0.1z)` gates with their `expLimit` saturation guards), the peephole LSTM forward (12-row peephole bundle, reverse pass as reverse-input -> forward -> reverse-output), the dense `NeuronLayer` (asinh hidden, unstabilized softmax output), the `Network<L>` container (`SubSample` integer-floor decimation, head-eating flat weight seam), and the BLSTM wrapper (input normalization, core fwd+rev -> HCAT -> output-MLP forward, the 4 windowed drivers -- truncate, two-sweeps, overlap, MLP-overlap -- and the top-level scoring forward with cost/`_NbOfClassif` accumulation). Scope is LSTM + dense only: SRN/CWRNN are dead code in the legacy (compile-time instantiations, zero live constructors) and the conv layer is broken-as-committed (UB with the real lid.config, orphaned weights) -- both stay stubs, documented in `IMPROVEMENTS.md`; `nn/train.rs` (iRPROP-) is Phase 3. The Phase 1 GEMM finding recurs, non-locally this time: Eigen's blocked products diverge from ascending-loop accumulation at the NN shapes (`lstm_input_gemm` k=23: 8750/19200 elements ~1 ULP off; `dense_gemm` k=48: 1890/2400; the recurrence GEMV and softmax row-sum are bit-exact), and the layer-0 input GEMM seeds the recurrence, so the divergence propagates through every timestep. The oracle strategy is therefore **reimpl-with-probes**: the harness LINKS the real vendored NN translation units (`BLSTMNeuralNetwork`/`LSTMLayer`/`NeuronLayer` + link-only `SRNLayer`/`CWRNNLayer`/`CostLaw`/`Rprop`), dumps the goldens from a diff-reviewed harness-local ascending-loop reimplementation of the forward chain, and PROBES the real compiled classes against it at every site (`manifest.json:nn_product_probes` + the NN_TOL records): all synthetic-net sites match at 0 ULP (incl. hidden states, double-width two-sweeps outputs, and the OverLap NaN rows), while the real-net sites show the expected small GEMM-order deltas (fullseq output 7 ULP, hidden states 735/2076 ULP at ~2e-15 absolute, E2E posteriors 15/5 ULP, E2E hidden states up to 32792 ULP at <= 2.554e-15 absolute for `e2e_full_bwd`) -- recorded in the manifest as Phase 4 calibration data, the same absorb-don't-hide posture as the Phase 1 DCT substitution. The **end-to-end real-net gate** (`phase2_e2e_gate.rs`) chains the Phase 1 feature pipeline under the REAL `1_worker_1.config` keys (a `201 x 11` input: `3*nb_DCT - 1` with `IgnoreFirstDCT`, no LTSV column) into the real 33,671-weight net and asserts the posteriors bit-exact vs the reimpl -- surfacing one real finding: the config's 11-wide features feed a net trained for 23 inputs, silently tolerated by the legacy width-tolerance branch (12 dead layer-0 weight rows; see `IMPROVEMENTS.md`). Provenance: the LSTM/dense/container/BLSTM forwards are compiled-TU-probed as above; the cost-quirk and in-place-mutation semantics are expression-coded unit tests; activations and the weight seam are pinned by harness dumps plus hand-computed boundary tests; a scalar-loop Python oracle (`nn_reference.py`) cross-checks the Rust layers bit-exactly from a structurally different implementation. Note: MATLAB's `BLSTM_Forward.m` was NOT the oracle and was not ported -- it implements different semantics than the engine (`sigmoid(x)` gates without the 0.1 pre-scale, no output softmax) and cannot match it; `nn_reference.py` implements ENGINE semantics instead.
- **Phase 2b - segmenter wiring (done).** Wires the per-file segmentation drivers into the ported layers: the real `Segmenter` trait, the `Segmenter`-base residue (`DriverConfig`, `results_to_segmentation`), the `run_pipeline` lift into `features::pipeline::build_input_sequence`, and all four drivers in `tasks/sad.rs` (Algo 1-4). Oracle strategy is the **SegProbe pattern**: the harness now LINKS six real segmenter translation units (`Segmenter.cpp`, `Segmentation.cpp`, `BLSTMSpectralSegmenter.cpp`, `BLSTMSignalSegmenter.cpp`, `LongTermSpectralVariation.cpp`, `TimeDomainCorrel.cpp`) and harness-local probe subclasses call the REAL compiled protected machinery (`buildFromConf`, `updateSegmentation`, `smoothSegmentation`, `results2segmentation`, param derivation, `getLTSV`, `getBLSTMInputSequence`, `getPitch`, `toFile_VRCTS`) -- only the `getSegmentation` bodies are transcribed, and only where an NN sits in the chain are the `feedForwardBackward` calls swapped for the existing bit-stable reimpl family. Why the swap instead of a real-Eigen bit-golden: the NN posteriors sit within 2-4e-16/frame of the decision thresholds on real data, boundary times are LINEAR INTERPOLATIONS of those posteriors (~1e-15 s jitter per crossing), and the hysteresis/area comparisons are DISCRETE -- a sub-ULP forward difference can flip a whole segment into or out of existence, so the real-Eigen forward is only trustworthy as a STRUCTURE oracle, never a bit one. `TdcSegmenter` (Algo 1) and `LtsvSegmenter` (Algo 2) have no NN in the chain at all, so their goldens run against the REAL compiled `getSegmentation` directly (LTSV's `nb_DCT=4` branch swaps only `applyDCT` for the ascending-loop `applyDCTLoop`, the same Eigen-GEMM-divergence workaround from Phase 1/2). `BlstmSignalSegmenter` (Algo 4) is the FIRST driver with the NN in the chain -- the raw 1-column signal feeds `nn/blstm.rs`'s `feed_forward_backward` (the real 23-input net runs on it via the LSTM input-projection `topRows` width tolerance) -- so its oracle is a REIMPL-SWAP (`SignalProbe`): `getSegmentation` transcribed faithfully, only the FFB call swapped, plus a SECONDARY real-forward structural probe (reimpl vs real-Eigen segment count+types must match exactly or the harness aborts; boundary max-dt recorded -- all three variants measured `0.0`). On this excerpt the real net's posteriors stay sub-threshold (~0.002-0.03 vs a 0.6 rising threshold), so every signal variant collapses to the untouched always-Other seed hypothesis `[Other@0, End@dur]` -- the NN chain itself is still pinned bit-exact via `last_result_rows`, but the decision layer is NOT exercised by these fixtures; the result-row pins carry the parity load here, not the boundaries. Three variants: `window0`, `overlap` (the only non-broken degenerate regime -- signal overlap mode is broken-as-committed for `window_shift > ssr`, see `IMPROVEMENTS.md` `signal-overlap-oob`), and `noOverlap` (the genuinely-stateful `_WindowShift = 0.0` poisoning, pinned by a two-files golden). `LtsvSegmenter`'s `is_log_mel=true` configs (the primary `ltsv.config` and its DCT/tiny siblings) are similarly decision-layer-blind on this excerpt -- the LTSV mean-floor assumes a power-scale periodogram, so log-scale input blows the score up to ~1e51 and every frame reads as SPEECH (see `IMPROVEMENTS.md`); the power-scale `ltsv_powermel` variant exists specifically to exercise real threshold crossings (a genuine SPEECH/OTHER/SPEECH structure on channel 1). `BlstmSpectralSegmenter` (Algo 3, the REAL `1_worker_1.config`'s algorithm) is COMPLETE including the pitch-homothety second pass (`BLSTMSpectralSegmenter.cpp:757-805`): `get_pitch` over the pass-1 segmentation (NN-free), `apply_homothety` warping the periodogram by `pitch/300`, re-filterbank/DCT, and a re-forward that rebuilds the input with the OLD (pass-1) LTSV column (a load-bearing quirk -- WIRED but unexercised on this config, since the real config's `LTSVwindow 0` means no LTSV column exists in either pass; see `IMPROVEMENTS.md`), then `clear_hypothesis` + re-segment. Its oracle `SpectralProbe` transcribes the full `getSegmentation` (calling `getTDCParam`/`getPitch` REAL, both NN-free) and swaps only the FFB calls for the reimpl, plus the same SECONDARY real-forward structural probe (all four variants `SEG_STRUCT max_dt=0.0`). UNLIKE signal, the real net genuinely crosses the rising threshold here, so the full decision layer (rising crossing + interpolation + hysteresis area) is exercised non-trivially, including the pitch pass: the `pitch` variant (TDCwindow 0.032, measured pitch ~250 Hz) is NON-VACUOUS -- the warp moves the chan-1 boundary from pass-1 1.1831 s to pass-2 1.2597 s, pinned by `spectral_pitch_*` goldens. The legacy dump quirk (externalized result stays PASS-1 while the boundaries are PASS-2) is reproduced and pinned. Separately, the Phase 0b-ii VRCTS-writer byte-golden deferral is now CLOSED: the harness's `iof::fmtr` shim was upgraded from inert to a FAITHFUL mini-formatter (`%f.Ns` == `std::fixed` + `setprecision(N)`), making the real compiled `toFile_VRCTS` itself a byte-golden source -- `to_vrcts_string` (the Rust writer) is asserted byte-for-byte equal to it across all four drivers' dumps (nine `.xml` fixtures total), closing the deferral without waiting on an end-to-end legacy run. Algo 1-4 are all landed; LID (Algo 5/6) + `TwinBLSTM` defer to Phase 4.
- **Phase 3 - network-level training (done).** The complete network-level BPTT + iRPROP- chain: `CostLaw` backward (`deriv()` per law, `computeUnitaryDeltas`/`computeDeltas` incl. the softmax+CE fusion and the `BackPropWER`/ponderation scaling -- already ported alongside the Phase 0b-i forward, now VALIDATED), `LstmLayer`/`NeuronLayer::feed_backward` (peephole BPTT with the O->state->C->F->I gate-derivative order; dense weight/bias deriv accumulation with NO output-activation Jacobian -- the fusion lives in `cost.rs`, proving the double-count trap doesn't bite), the `Network<L>` container backward (reverse-order layer loop, `InvSubSample` decimated-row re-expansion -- the SubSample crux resolved: rows are RE-EXPANDED, not dropped, though the floor's trailing `T mod R` frames stay gone), and the full `BlstmNetwork` backward (`feed_backward`/`feedBackwardDouble` fan-out, all 4 windowed drivers' backward halves, `get_weights_derivatives` Nx2 assembly, `reset_weights_derivatives`, `update_weights`). Oracle strategy is a **four-tier ladder, strongest first**: (1) `Rprop::updateWeights` probed against the REAL compiled class directly, strict bits on every platform, no canary (pure scalar, no libm/GEMM); (2) `CostLaw` backward probed against the REAL compiled class (polynomial laws bit-exact everywhere, Log/Sqrt canary-gated); (3) layer/container/BLSTM backward via a harness ascending-loop reimpl + NN_TOL probes of the real classes (all synthetic-shape sites `max_ulp=0`; real-net/output-ratio sites recorded as Phase 4 GEMM-divergence calibration, same blocked-vs-ascending story as the Phase 2 forward); (4) an independent Python engine-semantics backward oracle (`nn_reference.py`'s `lstm_backward_oracle`/`dense_backward_oracle`/`blstm_backward_oracle`) cross-checked bit-for-bit against the same harness fixtures the Rust suite consumes -- transitively triangulated through the shared fixtures, not a live PyO3 cross-call (the `speech-py` bridge is still an 18-line stub; that binding is Phase 4). The **real-net E2E gradient gate** (`phase3_e2e_grad_gate.rs`) chains the real 33,671-weight net's Nx2 gradient bit-exact vs the reimpl, then drives two `Rprop::update_weights` calls: the first step matches the real compiled trainer bit-exact, the second (cost negated) fires the cost-gated backtrack on 24409 of 33671 elements -- a genuine, non-vacuous majority, not a corner case. The network-level central-difference **grad check** (`phase3_gradcheck.rs`) spot-checks a synthetic net spanning every sub-network region (`[2,2]` LSTM + `[4,2]` output, 142 weights) against numerical central differences on 10 weights (the real net's gradient is pinned bit-exact by the E2E gate, not central differences): measured relative errors run `3.8e-11` to `1.4e-7`, comfortably inside the documented `5e-4` bound (mean-vs-max bound choice noted in the doc-comment). What's still deferred to **Phase 4**: the corpus epoch loop and cross-file gradient reduction (the legacy's OpenMP-critical sum is order-nondeterministic -- the Rust reduction must be deterministic when it lands, tracked in `IMPROVEMENTS.md`), `BagOfProcessors::saveAndUpdate`'s best-weight lifecycle, the corpus-level grad-check CLI mode (with its documented result-column indexing hazard), the CLI Train/GradCheck modes, the PyO3 seam, `scoring.py`'s `CheckGrad`, and the Python optimizer zoo (SMORMS3/QuantumPSO/CMA-ES stay stubs).
- **Phase 4 - engine drivers, LID, PyO3, end-to-end (done)** (decomposed into 4a-4d; all four sub-phases done).
  - **Phase 4a - corpus/engine drivers + CLI (done).** The three-module driver stack lands: `engine/corpus.rs` (`fileslisting`/`language2classmapping` CSV parsing into `CorpusItem`s, reproducing the `istringstream >>` extraction quirks -- `"0.5abc"` fails, `"0.5z"` extracts 0.5 -- and the listing token-parse SIBLING semantics: the `tokens.size() > 4` fileId check sits beside the `tokens[3].size() > 0` weight check, not nested in it), `engine/bag_of_processors.rs` (a `Processor` enum over the FOUR concrete drivers `Tdc`/`Ltsv`/`Spectral`/`Signal` -- an enum, NOT `Vec<Box<dyn Segmenter>>`, since the algo set is closed and static dispatch keeps each driver's concrete `set_weights`/`get_weights_derivatives` reachable; the tag replaces the legacy `_AlgoTypes` if/else ladder -- plus the ctor key-clears, per-file/per-channel `segmentation_function` with STM/CSV reference load and the scored/unscored 18-column result assembly, and `save_and_update`'s best-weight save gate + count-normalized aggregation + the `costLID = -1.0` no-speech gate ordered save->gate->update), and `engine/corpus_processor.rs` (ctor output-truncation/epochs-clamp/`_BestCost`-seed, the mode-gated `run` dispatch over solo/train/gradCheck with the gradCheck permanent mode-flip, and the epoch loop). The legacy's `#pragma omp parallel for schedule(dynamic,1)` + `omp critical` fold -- nondeterministic even at a fixed thread count, because the derivative `+=` and `InputStatistics::update` merge are float-order-sensitive -- is replaced by a DETERMINISTIC **static-lane model** (spec S3, the R6 determinism fix, the ONE deliberate deviation from legacy parallelism): file `j` -> lane `j % N` (`N` clamped `[1, nb_files]`), each lane clones the epoch-start bag once (`firstprivate`) and walks its files in ascending `j` so genuine cross-file driver state chains within a lane, then folds in ascending file index after the `rayon::scope`. At **N=1 this is byte-identical to a plain sequential loop -- the golden-pinned parity mode**; for N>1 the results are deterministic (fixed for a fixed N) but differ from the legacy's nondeterministic run AND, because state chains per lane, from N=1 (measured: the noOverlap signal config's `_WindowShift` poisoning chains differently under N=1 vs N=2). Oracle strategy is **two tiers**.
